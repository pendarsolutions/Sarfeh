Sarfeh 0.5.0 shows what can be known about the hardware under a server, and brings the price page what its first
readers asked for.

## Added

- **The CPU model of each server, and the CPU time its host takes away.** The Servers page shows the processor each
  server reports (or says that the host hides it), and the share of its CPU time the host gave to other machines, as
  a 95th percentile. From 10% it warns: the host is oversold, and the server is slower than its size suggests. CPU
  use still includes that time, so a server starved by its host is never advised to shrink.
- **ArvanCloud's prices of 24 November 2026**, about 20% above the ones the catalog starts with. ArvanCloud's site
  can't be read automatically, so they come as a reviewed price file. To apply it:

  ```bash
  sudo sarfeh compose exec api python -m finops_api.cli price-import --provider arvancloud \
    --file /app/data/price-files/arvancloud-2026-11-24.json
  ```

On the public [price page](https://pendarsolutions.ir/sarfeh/prices/):

- **What each figure assumes or leaves out** is written under it: an IPv4 address assumed to come with the plan (or
  its price where one is charged), a price that is for 30 days, ParsPack's setup fee equal to 7 days.
- **Price changes** have their own tab: which provider moved which plan, from what to what, and when. The same
  record is open as [changes.json](https://pendarsolutions.ir/sarfeh/changes.json).
- It says when a provider doesn't state whether its CPU is shared or dedicated, and shows the CPU model beside a
  plan once a user has [reported it](https://github.com/{{REPO}}/issues/new?template=cpu-model.md).

## Fixed

- **ParsPack prices stopped updating** when one of its datacenters listed its control-panel licences at another
  price. Only the CPU, memory and disk prices that are read are compared now.
- Server.ir's retired IRAT plans no longer raise a warning on every price update.

## After upgrading

Servers you added before this version keep the older collector script, which doesn't read the CPU model or the
host's share. Run the setup command from the **Servers** page on each of them once more (it is safe to repeat), and
both appear from the next collection. The page says which servers need it.

## Upgrade

```bash
sudo sarfeh upgrade
```

It backs up first, then moves to 0.5.0 and keeps your settings and data. On 0.3.x the command is still called
`finops-agent` (`sudo finops-agent upgrade`); from 0.2.0 or earlier, run the installer:

```bash
curl -fsSL https://github.com/{{REPO}}/releases/download/v{{VERSION}}/install.sh | sudo bash
```

The full list of changes is in the [changelog](https://github.com/{{REPO}}/blob/v{{VERSION}}/CHANGELOG.md).
